# HL 运营后台界面规范

## 目标与方向

供运营人员集中审核主理人、会员认证和沙龙，并查看套餐与订单。延续小程序的暖米白、陶土棕及深棕文字，用明确的层级降低日常查找成本。

视觉方向为精致克制的工作台（Luxury / refined），左侧导航与右侧工作区形成不对称布局。字体沿用已有品牌 PingFang SC / Microsoft YaHei，不另行引入网络字体。

## 布局及排版

- 六页共用导航、标题、卡片和筛选规范。六页为既有业务范围。
- 桌面内容内边距 32px，窄屏 16px；卡片间距 16–24px，圆角 10px。
- 页面标题 28–30px，分区标题 18px，正文 14px，辅助说明 12–13px。
- 所有原生文本组件明确使用带单位行高，不传 `"1.7"` 一类无单位字符串。
- 按钮最小高度 42px，文本行高 22px；手机端允许按钮组折行。
- 驾驶舱关键指标桌面六列，中等宽度三列、手机两列；增长与收款趋势采用宽图区搭配窄结构区，手机顺排。
- 表格在独立容器内横向滚动，筛选和详情不随表格溢出。
- 原生微搭 CALS 是交付源，使用全局 CSS 与组件样式配合，不引入另一套 Web 框架或 Tailwind 构建链。

## 当前状态

本次是已创建微搭应用的界面重设计。统计使用破折号表示尚未取得数据，列表不制造业务记录；业务操作继续禁用，导航保留。云端保存历史前备份当前草稿，并以该历史号作为并发保护基线。

## 运营驾驶舱

运营总览增加会员档案数、新增会员、认证主理人、实付金额、退款金额和净收款六项指标，默认周期为北京时间近30天。分析包括会员新增/累计趋势、会员权益和认证状态、经营收款趋势、套餐收款构成，以及主理人认证/近期使用/所在地/名下会员分布。用户明确选择经营收款，不加入主理人收款业绩。

图表采用当前官方原生 `Line` 与 `Pie`。数据源显式设为 `variable` 和空数组，避免默认图表的内置示例曲线。未接入时显示空坐标轴和说明，圆环为无分段的中性空态，不代表套餐占比。周期标签在此设计阶段只是范围说明，不暗示可执行筛选。

指标严格区分当前存量、近30天增量和现金口径；净收款不是会计收入。数据映射与尚未实现的聚合接口见 `cockpit-metrics.md`。驾驶舱更新只替换 overview，保留其他五页、编辑器模板及登录配置。

## 验收要求

结构和组件属性检查之外，分别检查桌面和窄屏的文字、按钮、导航与表格。官方同版本组件渲染、本地模拟预览、云端编辑器预览必须区分记录，不能把其中一种当成另一种的验收。
