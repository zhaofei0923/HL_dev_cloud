# IF.U 免登录浏览审核整改说明

编制日期：2026-10-20。对应审核问题：首次进入首页，用户尚未浏览功能服务就被要求授权登录。

## 调整后的用户流程

1. 首次进入首页即展示活动与服务介绍，不自动调用微信登录，不要求手机号、头像或昵称。
2. 游客可浏览近期与往期活动、活动详情及当前已启用服务方案。没有活动时显示真实空状态，服务介绍仍可阅读；读取失败提供重试，不以登录作为恢复条件。
3. “推荐、消息、我的”在未登录时显示对应功能说明、自愿登录和浏览活动入口，不自动跳转登录，也不读取旧账号私人信息。
4. 只有主动点击报名后才进入现有微信登录和活动资料填写流程。保存资料后返回活动详情，还需本人再次确认报名；不会自动报名或改变主理人归属。
5. 邀请链接先显示说明，用户主动确认后才登录并直接加入免费会员，不增加管理员审核步骤。
6. 登录取消或失败后仍可继续浏览公开内容。手机号授权继续保留在相应业务操作的主动按钮中；查看公开活动或服务介绍不触发手机号授权。

## 接口和权限边界

新增的三个接口均只读，位于集合初始化、种子数据和业务登录校验之前：

| 接口 | 公开内容 |
| --- | --- |
| `GET /public/salon/events` | 近期或往期活动基础字段，有界分页。 |
| `GET /public/salon/events/:id` | 已公开活动的标题、介绍、地点、日期、价格与名额等基础信息。 |
| `GET /public/service-plans` | 当前启用的固定套餐名称、价格、期限和服务次数。 |

公开活动采用独立 DTO 白名单，不复用展开整条活动记录的登录接口，不读取用户、资料或报名集合。未公开活动不可访问，不返回组织者身份、报名人、个人资料、审核备注或资料完整度。

这些读取不创建账号、集合或示例数据；集合不存在返回真实空结果，数据库故障返回脱敏错误。原有会员档案、报名名单、报名写入、聊天、订单、支付、认证和后台路由继续鉴权。

客户端公开读取使用 `auth:false`、`showError:false` 和 `preserveSessionOnUnauthorized:true`，服务异常不会强制跳转登录。页面响应继续核对环境、账号、请求代次和页面生命周期，退出后清空私人内容。
