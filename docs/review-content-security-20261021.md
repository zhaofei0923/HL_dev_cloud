# 微信用户内容安全审核整改说明

日期：2026-10-21。对应审核意见中的“头像功能进行内容安全验证时存在风险”，以及各发布场景应接入内容安全 API 的要求。

## 已修改行为

新增统一服务端检测模块 `cloudfunctions/hlApi/content-security.js`，通过 `cloud.openapi.security.msgSecCheck` 调用 V2 接口。只有明确返回 `result.suggest: pass` 才继续业务写入；`risky`、`review`、87014、接口异常、权限未配置和不完整返回均停止本次提交。前端沿用现有错误提示，不将 SDK 原始诊断返回用户。

| 提交入口 | 检测内容 |
| --- | --- |
| 微信登录 | 提交的昵称；系统生成的默认编号名称无需检测 |
| 活动报名资料 | 本人称呼 |
| 个人资料、主理人编辑会员 | 姓名、昵称、介绍、择偶要求及其他文字资料；年龄、身高另做数值校验 |
| 主理人人工建档 | 实际进入展示资料的文字，包含从完整登记表生成的介绍及择偶要求 |
| 开启资料展示 | 合并已有资料与本次修改后重新检测，不能仅通过展示开关发布未检测文字 |
| 活动新增与修改 | 标题、介绍、地点；修改时检测最终文字内容 |
| 聊天文本 | 发送给对方的实际文字 |
| 邀请、申请、推荐及牵线留言 | 实际保存或发送给其他用户的留言与备注 |

普通资料使用场景值1，聊天及留言使用2，活动使用3。检查使用云端已验证身份的 OpenID：主理人代录或编辑会员时使用主理人身份，不使用被录入会员的占位身份，也不接受请求数据中的 OpenID。

检测在内容写入、对应业务编号分配和消息投递之前完成。长文本按 Unicode 字符分段，每段最多2500字符，段间保留128字符重叠，最多8次检测；任一段失败即停止保存。日志仅保留检测状态、可用的微信追踪编号及数值错误码，不记录提交正文、OpenID或原始 SDK 错误。

图片检测通过 `cloud.openapi.security.imgSecCheck` 同步执行：服务端下载当前环境的原始文件，检查真实 JPEG/PNG 格式、静态图片结构、尺寸不超过750×1334、文件不超过1,000,000字节，再调用微信检测。明确返回成功才继续；87014、非零错误、无明确结果、超限、外部网址、跨环境和私有认证材料均不能进入公开图片保存链路。

登录头像、报名本人照片、本人资料、主理人代录或编辑会员照片、开启资料展示时的已有照片、活动新增与修改时的封面都接入图片检测。只有服务端业务逻辑允许时，精确白名单内的项目自带静态图片才可跳过检测；请求中的“已检测通过”标记不会被采用。

整批图片全部通过后，服务端将实际检测的相同字节保存至 `hl_moderated/images/<SHA256>.<jpg|png>`，业务资料只存副本ID。原始上传文件仍在 `hl_uploads/`，不会把待检测图片提前替换成已保存头像。资料编辑接口将持久文件ID与短期展示URL分别返回，避免用户把临时URL再次提交为照片。

未接入异步媒体回调的“新语音发送”本版暂时关闭，旧录制方法与直接请求同样受阻；文字聊天与历史语音播放可继续使用。

用户提示仅说明内容含有违规信息、图片需重新选择，或暂时无法提交；不暴露原始 SDK 错误、审核标签或命中规则。`cloudfunctions/hlApi/config.json` 已声明 `security.msgSecCheck` 和 `security.imgSecCheck`，保留原有手机号和小程序码权限。

## 范围与限制

本次同时覆盖文字和公开图片提交；认证PDF/图片材料继续使用原私有审核流程，不将其复制到公开头像或封面路径。历史已公开内容未做批量改写；修改资料、重新开启展示或修改活动会重新检查最终提交内容。平台是否判定某张图或某段文字违规，只能以真实微信接口结果为准，本地模拟不可替代。

审核整改说明可填写：

> 已补齐头像、本人照片、活动封面及文字发布的服务端内容安全检测。检测通过后才保存和展示，违规或检测异常均停止提交；各入口统一处理，用户只收到简短违规提示。未接入检测的新语音发送已暂停。
