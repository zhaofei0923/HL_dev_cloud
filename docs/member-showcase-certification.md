## 分类接口

`GET /member/showcase` 接受 `category=recommend|popularity|education|assets`，省略时为 `recommend`。四类继续使用现有城市、性别、学历、年龄等筛选条件，以及原有分页契约。

| 分类 | 准入 | 顺序 |
| --- | --- | --- |
| 推荐 | 原有公开展示规则 | 保持原有排序 |
| 颜值 | 至少 101 位不同有效用户的有效爱心 | 爱心人数降序，同人数使用原有排序 |
| 学历 | 已核验本科、硕士、博士 | 博士、硕士、本科，同层级使用原有排序 |
| 资产 | 已核验金融资产至少 200 万元，且本人明确同意进入分类 | 先应用共同筛选条件，再按已核验金融资产档位降序，同档使用原有排序 |

颜值统计每个发送者与接收者的最后一条 `favorite` 状态。赠礼已经由现有流程转为同一对用户的爱心，不另加赠礼数量。撤回、失效、过期、已注销、已合并及不存在账号的爱心不计；重复爱心只计一人。页面说明使用“收到超过 100 人爱心的会员”。

学历来源仅接受 `chsi`（国内学信网核验）和 `cscse`（国、境外留服学历学位认证）。海外、港澳台及中外合作办学取得的境外学历学位，按认证结果录入统一的本科、硕士、博士对应层级；同层级不会因国别、留学经历或学校排名加权。不能确认层级、待核验、审核驳回或已撤销的结果不得入选。

金融资产档位沿用现有私密档案中的枚举：

| 值 | 审核归档口径（人民币） | 进入资产分类 |
| --- | --- | --- |
| `under_500k` | 低于 50 万元 | 否 |
| `500k_2m` | 至少 50 万元、低于 200 万元 | 否 |
| `2m_5m` | 至少 200 万元、低于 500 万元 | 是，另需本人同意 |
| `5m_10m` | 至少 500 万元、低于 1,000 万元 | 是，另需本人同意 |
| `over_10m` | 至少 1,000 万元 | 是，另需本人同意 |

房产数量、车辆数量、收入不能转换成金融资产档位；现有 `hl_member_private_archives.assetVerification.financialAssetRange` 属于档案收集值，必须另经管理员审核后才生效。恰好 200 万元应审核归入 `2m_5m`。

`GET /member/showcase/:id` 返回单个最新公开会员 DTO；`:id` 使用列表中的数值会员 ID 或 `profile_数字`。它只读取公开资料，不读取内部档案。本人、已隐藏、已关闭展示、已失效账号或公开身份已变化时返回 404。

公开列表及详情提供：

```json
{
  "educationVerified": true,
  "verifiedEducation": "硕士",
  "assetVerified": true
}
```

仅当本人 `assetRangeDisclosure === true` 且金融资产核验仍有效，才补充 `financialAssetRange` 枚举。证据、审核备注、审核人、来源、原始认证摘要、未公开金融档位和分类同意字段均不进入公开会员 DTO。

## 本人选择

“我的资料”新增实名、学历、车辆、房产、资产五项认证入口，使用本人 access 会话调用 `GET /user/certifications`。该接口只读取当前账号的 `hl_member_certifications/user_用户ID`，按固定顺序返回五项 `entries`；没有记录时显示 `unsubmitted`，不会创建资料或认证记录。返回字段限定为类型、申请/审核状态、是否已核验、对应学历或本人可见金融资产档位、来源、提交/审核时间、本人可见反馈以及最少申请信息。证据引用、审核内部备注、审核人、管理员会话、审核历史、申请内部 ID 不返回给本人。

本人认证流程已改为小程序内提交材料。本节所述上传和加密接口对应前文认证材料版本的部署记录；仅四分类版本的验收不能代替上传流程验收。审核仍由工作人员人工核对，上传成功或提交成功不等于认证通过。

先调用 `POST /user/certification-materials`，请求字段仅接受 `kind`、`mimeType`、`contentBase64`。材料只接受 JPEG、PNG 图片及 PDF，文件头须与声明的 MIME 相符，每份不超过 500 KiB（512,000 字节），每类型最多暂存 3 份。本接口不接收原文件名、证件号码、银行账号、第三方 fileID 或公开 URL。

服务端先验证格式和大小，再使用 AES-256-GCM 加密文件；只有密文 Buffer 交给 `cloud.uploadFile`。云路径为 `hl_uploads/member-certification-encrypted/随机材料ID.enc`，不含用户 ID、学校、证件信息或原文件名。同一明文每次加密均使用新随机 IV，认证附加数据绑定本人用户 ID、认证类型、材料 ID、用途和版本。存储文件引用只存在同一受限认证文档的 `materials` 元数据中；本人及管理员列表均不返回云文件引用、下载 URL 或加密封装。

上传返回 `{ "material": { "id": "随机材料ID", "kind": "education", "mimeType": "image/jpeg", "size": 12345, "createdAt": "服务端时间" } }`。随后调用 `POST /user/certification-requests` 关联这些材料 ID。本人预览使用 `GET /user/certification-materials/:id`，只有当前本人账号可取回解密后的 `contentBase64`；服务端再次核对实际文件格式和大小。`DELETE /user/certification-materials/:id` 只移除本人尚未提交的材料；关联当前或历史申请后不能通过该接口删除。未关联材料的暂存有效期为 24 小时，过期后不可读取或提交，下一次本人上传时才触发清理，并非 24 小时后定时物理删除。清理先事务标记 `deleting`，再删密文和元数据；云删除失败则保留不可读取/提交的状态，下次上传继续重试，不清理任何已关联申请材料。

```json
{
  "kind": "education",
  "source": "cscse",
  "educationLevel": "master",
  "institutionName": "最高已取得学历对应学校",
  "method": "diploma_photo",
  "materialIds": ["已上传的本人学历材料ID"],
  "consentConfirmed": true
}
```

学历来源与通过规则相同：国内使用 `chsi`，海外、港澳台及中外合作办学境外学历使用 `cscse`。本人申请层级只接受 `bachelors`、`master`、`doctor`，对应已取得的本科、硕士、博士；学校必填，最多 120 字。旧本人申请中的中文学历在概览中转换为该英文枚举；管理员录入已核验结论仍使用中文层级，不改已有分类排序。

学历支持四种申请方式：`chsi_code` 必须使用 `source: chsi` 并填写 `verificationCode`；`cscse_number` 必须使用 `source: cscse` 并填写 `certificateNumber`；`diploma_photo` 与 `study_proof` 必须选择 `chsi` 或 `cscse` 并上传 1 至 3 份对应材料。验证码及编号方式可不上传材料，其他方式不接收这两个敏感字段。验证报告验证码、认证编号均仅加密暂存，不进入本人概览、公开资料、管理员列表或日志；只有专用管理员证据读取接口解密返回。

其他四类型申请必须关联至少 1 份、最多 3 份本人同类型材料，不接受学历方式字段。来源由服务端固定为实名 `identity_document`、车辆 `vehicle_license`、房产 `property_certificate`、金融资产 `combined_financial_statement`。金融资产可选填 `declaredFinancialAssetRange`，使用现有金融档位枚举；此自报档位也只加密暂存，不用于入选、排序、公开资产区间或管理员核验结论。审核人员仍需核对材料后另行录入已核验档位。所有申请值均为待核验信息。

申请返回同一个本人概览，申请信息只增加方法及材料 ID，不返回验证码、编号、自报金融档位或加密封装。重复提交同类型的待审申请直接返回原申请，不另写记录或修改提交时间；待审期间不同自报值也不会替换原申请。已提交材料在同一数据库事务中从 `staging` 改为 `bound`，跨账号、跨类型、过期、已删除或已关联材料均不能绑定。缺少已保存本人资料时返回 422 和“请先保存我的资料，再申请认证”，不会代建公开资料。提交申请不修改已有审核结论、公开认证标记、进入资产分类同意或区间公开选项。已有认证后重新申请时，`status` 为 `pending` 而 `verified` 可继续为 `true`，已核验层级/档位保留；资格只在管理员修改该类型结论后变化。客户端认证标志应依据独立的 `verified` 字段。

审核结果显示 `approved`、`rejected` 或 `revoked`。本人只看到管理员单独填写的 `feedback`，不以内部 `remark` 作为反馈；反馈最多 500 字。新申请进入待审后不继续展示上一轮的反馈。相同类型新一轮申请可保留最少必要旧申请历史（最近 25 条），存放在同一受限认证记录中，审核历史继续使用原有私密审核记录。

本人通过现有 `PUT /user/profile` 保存以下两个严格 Boolean 字段：

```json
{
  "assetCategoryConsent": true,
  "assetRangeDisclosure": false
}
```

默认均为 false。两个选择相互独立：同意进入资产分类不等于同意公开档位。发送字符串、数字等非 Boolean 值返回 422。主理人更新会员资料不能代本人设置这两个选项；自填认证字段会被白名单剔除。更改本人选择不会改动原始审核记录。

## 管理员录入流程

1. 使用现有 `POST /admin/login` 登录，获得 `admin` 类型 token；普通用户或主理人 token 无法访问审核接口。
2. 核对会员 `userId` 与材料归属，实名人工核对有效身份证明，车辆核对车辆行驶证，房产核对产权证明，学历查看国内学信网或境外留服可查验结果。金融资产核验核对金融材料和归档区间；证据应留存在受限位置。此处均为人工审核，不提供外部实时核验接口。
3. 调用 `PUT /admin/member-certifications/:userId` 写入审核结论。审核通过必须填写有效来源、对应层级或档位、内部证据引用。
4. 使用 `GET /admin/member-certifications?userId=数字` 查看私密审核记录和历史。每次审核保留审核时间、审核来源、证据引用、备注及审核管理员会话。
5. 原结果失效时，用相同接口提交 `status: revoked`；驳回则提交 `status: rejected`。这两种操作立即取消对应认证，其他已核验类别和本人选择保持原值。有本人申请时，同时更新该类型当前申请状态。

管理员必须配置有效的 `ADMIN_CODE`；缺失、空白或公开默认值 `HLADMIN` 会使管理员登录以 503 拒绝，不能用默认码获取核验权限。全部 `/admin/member-certifications` 专用接口同时检查当前管理员码配置、本次版本登录签发的 `certificationAdminVersion: 1` 会话标记，以及由 JWT 密钥和当前管理员码生成的会话凭据指纹；指纹采用固定域 HMAC-SHA256，校验使用常量时间比较。旧管理员 token 或管理员码变更前签发的认证 token 需重新登录，否则返回 40102，不能靠此前默认码签发的会话绕过。其他原管理员路由保持兼容，现有有效管理员码无需更换。当前仓库没有认证管理网页；本次审核使用管理员运维 API，普通 CMS 仍不得直接编辑认证集合。

查看本轮材料使用 `GET /admin/member-certifications/:userId/applications/:kind/evidence`，返回当前 `applicationId`、方法、来源、学校、已取得学历、材料安全元数据，并仅在对应申请包含该项时解密返回验证码、认证编号或自报金融档位。可附 `applicationId` 做旧页面校验，ID 变化时返回 409。实际图片/PDF 使用 `GET /admin/member-certifications/:userId/materials/:id` 取回解密 `contentBase64`；该接口只允许管理员读取该会员已提交绑定材料，不读取用户尚未提交的暂存材料。两种接口均先校验管理员 token，不能使用普通用户或主理人 token。

当前类型存在待审申请时，审核请求必须补充 `applicationId`，值取管理员列表中 `applications[类型].requestId`。不提供返回 422；ID 与当前申请不匹配返回 409，需重新读取和核对材料，避免旧审核页面处理新一轮申请。没有待审申请时仍可按原流程直接录入或撤销，但如主动提供申请 ID，也必须与当前申请匹配。申请 ID、证据引用和审核内部信息仅在管理员接口出现。

管理员 `kind` 接受 `identity`、`education`、`vehicle`、`property`、`assets`。实名、车辆、房产的审核来源分别只接受 `identity_document`、`vehicle_license`、`property_certificate`，通过时同样必须填写内部受限证据引用，不接收公开证件内容。公开资料只新增服务端生成的 `identityVerified`、`vehicleVerified`、`propertyVerified` 布尔标志；旧的 `isVerified` 或自行填写字段不代替这些人工核验结果。车辆和房产核验也不会产生金融资产档位或资产分类资格。

`remark` 仅用于管理员内部审计，`feedback` 为本人可见的独立审核反馈，不得在 `feedback` 中复制证件、账户、内部档案位置等敏感信息。例如驳回时可填写 `"feedback": "请联系主理人补充可查验的学历认证结果"`；省略该字段不向本人显示内部备注。

境外、港澳台学历通过示例：

```json
{
  "kind": "education",
  "status": "approved",
  "source": "cscse",
  "educationLevel": "硕士",
  "evidenceReference": "内部受限档案记录ID（勿填验证码或原始认证编号）",
  "remark": "已核对证书持有人及认证结果对应层级"
}
```

国内学历将 `source` 改为 `chsi`。`educationLevel` 仅接受本科、硕士、博士；每次填写已核验的最高有效对应层级，不复制用户自填字段。最新审核替换该类型的当前结论，历史记录仍保留；更正层级也使用同一接口。海外学历不会自动获得额外排序权重。

金融资产通过示例：

```json
{
  "kind": "assets",
  "status": "approved",
  "source": "combined_financial_statement",
  "financialAssetRange": "2m_5m",
  "evidenceReference": "内部受限金融材料索引",
  "remark": "已核对金融资产合计及人民币归档区间"
}
```

金融来源仅接受 `bank_statement`、`securities_statement`、`combined_financial_statement`。这次审核不会替本人同意分类，也不会打开区间公开。

撤销示例：

```json
{
  "kind": "education",
  "status": "revoked",
  "remark": "原核验结果失效，等待重新核验"
}
```

当前管理员登录采用共享管理员码，因此审核记录能追踪 `shared-admin` 账号及服务端签发的 `adminSessionId`，无法证明具体个人身份。需要个人责任归属时，应另行升级管理员独立账号，不以客户端自报姓名代替身份。

## 数据与发布前设置

- 新增 `hl_member_certifications` 受限集合，按 `user_用户ID` 保存当前结论、各类型当前本人申请、最少旧申请信息及追加审核历史。普通用户、主理人、小程序端和普通 CMS 运营角色不得直接读写该集合；本人只能通过服务端接口读取本人白名单概览、上传加密材料和提交申请。
- 材料元数据与加密验证码/编号/自报档位也保存在同一受限认证文档，不新增公开材料集合。仅服务端访问云密文存储，不生成明文临时 URL；存储安全规则与集合规则均须在云端确认。本人预览只经已验证本人会话解密，后台证据查看只经管理员会话解密。
- 认证路由不日志记录请求正文、原文件名、原始 SDK 错误或文件引用；预期错误只记录服务端安全错误码，未知数据库/存储诊断转为通用 503。审核人员不得把解密得到的验证码、原始认证编号或金融自报档位复制到明文 `evidenceReference`、`remark`、`feedback` 或其他公开资料。
- 加密专用环境变量为 `MEMBER_CERTIFICATION_ENCRYPTION_KEY`，格式为 `hex:` 加 64 位十六进制或 `base64:` 加标准 32 字节密钥编码。没有专用密钥时使用 `JWT_SECRET` 通过固定域 HMAC-SHA256 派生独立加密密钥；配置了格式错误的专用密钥不会静默降级。密钥缺失/错误返回 503，材料或加密记录无效返回 422。不得把密钥写入客户端、仓库、文档或日志。记录保存密钥来源，可在新增专用密钥后继续读取原 JWT 派生密文；更换原 JWT 或专用密钥前需保留旧密钥并安排已有记录迁移，不能把登录密钥轮换当作自动材料迁移。
- 云存储与数据库并非跨服务原子事务。上传后的数据库事务失败会补偿删除该次密文；如果数据库写失败且云删除也失败，会留下不含明文的孤立密文，需要管理员按上传错误记录和密文路径排查，不宣称数据库回滚等于存储已清空。不得为清理自行删除任何已关联申请材料。
- `hl_profiles.showcaseCertification` 为服务端控制摘要，只存排序必需的已核验状态、来源、层级或档位。禁止客户端直接读写 `hl_profiles`；若已有 CMS 写权限，必须把 `showcaseCertification` 与本人同意选项设为隐藏、不可编辑，仅由相应云函数流程写入。
- 管理员审核以数据库事务同时保存私密记录和资料摘要；只更新审核摘要字段，不覆盖本人选择、主理人 intake 或其他资料。
- 本人资料接口和会员申请资料会过滤内部摘要与原始认证字段。公开会员列表、关系页面、资源池和公开详情复用统一认证投影。
- 录入核验结果前，须在控制台确认集合及上述权限。此前分类版本与本次认证材料版本均已完成云函数部署，没有修改线上集合安全规则或 CMS 权限。管理工具确认了认证集合存在；其结构查询不提供安全规则。客户端只读统计探针也不能证明全部读写规则：`hl_profiles` 统计调用成功，`hl_member_certifications` 返回错误码 `-502005`，未将该错误当作权限拒绝。因此完整集合规则、写权限及普通 CMS 权限仍未核实，不能据此宣称已经禁止所有客户端访问。密文保护不代替数据库写权限；须防止客户端直接改写认证结论及公开摘要。

没有符合门槛的会员时返回空列表和真实总数，不回退到其他类别，也不降低门槛。“不再查看”继续按用户在四类中统一生效。

## 体验优化的配套接口

- 推荐筛选区分草稿和已应用条件。仅点击“应用筛选”后更新四类共用条件；返回各分类仍保留浏览位置。
- `GET /member/hidden` 仅列出当前会话用户主动隐藏的会员，分页最多 20 条；暂停公开的资料使用通用名称。`POST /member/interactions` 使用 `actionType: "hide"`、`active: false` 恢复本人已有隐藏记录，不创建不存在的记录。客户端必须收到 `viewerState.isHidden === false` 才显示恢复成功，并刷新四类缓存。
- 公开详情的 `viewerState.chatAccess` 为 `allowed`、`membership_required` 或 `unavailable`，依据现有主理人服务、正式配对及互相喜欢权限计算。旧接口未返回该字段时，页面提示刷新状态，不猜测聊天权限。
- 活动列表支持 `period=upcoming|past`，先按状态和时间分类，再分页；往期列表不包含待审核或审核驳回活动。省略该参数保留原有接口行为。
- 资料文字统一点击保存，照片与公开开关只提交各自字段；认证材料逐份显示结果并可单独重试，未提交信息不写入持久本地草稿。

以上接口改动须与对应小程序代码配套发布。微信支付最终状态仍以服务端订单为准；支付函数调用失败或用户取消后可复用原订单继续支付，已拉起支付但结果不明时先查询订单，避免重复创建付款请求。
