## 使用方式与身份边界

管理员仍按现有微信登录流程登录小程序，在“我的”页看到“管理后台”。普通会员和主理人默认不显示该项；服务端未授权时，即使篡改本地角色或直接打开页面，也不会取得后台地址。

页面每次显示和点击入口时分别查询权限，进入 `pages/admin/portal` 后再次核验。请求失败、换号、离页或退出登录会清除入口资格和页面地址，旧请求不能恢复新账号的入口。后台尚未就绪时，已授权账号可以看到明确的“管理后台尚未开放”状态。

入口打开现有微搭后台，不新增第二套管理业务界面。微搭继续使用自己的内部管理员登录和逐次服务端授权；小程序入口资格不授予微搭管理权限，也不签发业务管理员令牌。不把 JWT、管理码、OpenID 或其他登录凭据放入 URL，不实现单点登录。门户禁用转发菜单，离页清除 web-view 地址。

## 服务端配置

只为现有环境 `cloud1-d2gza7q9c8d69c721` 的 `hlApi` 配置以下两项，前端不保存名单或地址配置：

| 配置 | 合同 |
| --- | --- |
| `MINIPROGRAM_ADMIN_USER_IDS` | 经用户确认、数据库核对的业务用户 ID，使用英文逗号分隔；必须全部为正安全整数。缺失或任一值非法时，全部拒绝授权。不要填写微搭 UID、手机号或昵称。 |
| `WEDA_ADMIN_URL` | 发布后实际返回且经过访问验收的固定 HTTPS 入口。不使用编辑器、临时预览、猜测的应用路径；禁止 URL 凭据、query、fragment、空白和反斜线。缺失或非法时，已授权用户仅看到尚未开放。 |

`GET /user/admin-entry` 走现有 access-token 校验，再读取当前有效用户，检查账号状态、合并状态及 authVersion。逐次读取服务器配置，撤销名单后后续请求即拒绝；不信任请求或本地用户对象中的 role、allowed、userId、url 等授权声明。

响应仅有以下三种，不返回管理员名单、会员身份明细或凭据：

```json
{ "allowed": false, "ready": false }
{ "allowed": true, "ready": false }
{ "allowed": true, "ready": true, "url": "https://admin.example.invalid/" }
```

最后一项仅为合同示例，不能将示例地址配置到云端。
