# IF.U 用户隐私保护指引整改填写稿

日期：2026-10-22。依据本次审核截图及当前小程序源码核对。

## 本次需要纠正的内容

审核截图中的自定义条目出现“信息名称填……用途填……”等操作说明。这些文字不是正式的信息收集声明，不应保留在用户可见的指引中。

在微信公众平台进入“小程序设置 → 基本设置 → 服务内容声明 → 用户隐私保护指引”，编辑该自定义条目。下方名称与用途分别填入对应的输入框，只复制内容，不复制章节标题或填写提示。

### 信息名称

会员婚恋资料、择偶偏好与自愿认证信息

### 用途

在用户主动完善资料、申请认证或委托主理人建档时，收集其填写的年龄、城市、身高、学历、职业收入、婚况子女、房车概况及择偶要求，用于会员建档、匹配推荐和主理人服务；用户自愿提交的证明材料仅用于对应的身份、学历、车辆、房产或资产核验，不向其他会员公开。

## 其他已使用信息类型的填写参考

应优先使用后台已有的标准信息类型，不把全部收集内容只归入“自定义”。以下为源码中实际使用场景；编辑前以后台当前条目为准，未使用的类型不要为凑齐模板而添加。

| 后台信息类型 | 可填写的实际用途与场景 |
| --- | --- |
| 手机号 | 用户主动报名活动、开通服务或认领会员档案时绑定联系电话，用于身份关联、报名和已购买服务联系；受用户委托建档时由主理人登记联系电话。 |
| 选中的照片或视频信息 | 用户主动上传本人头像、生活照片、活动封面或认证图片时，接收选中的照片，用于对应的资料展示、活动介绍或认证核验。现有功能不上传视频。 |
| 选中的文件 | 用户主动申请认证并选择证明文件时，接收其选中的图片或PDF，用于对应的身份、学历、车辆、房产或资产核验，不读取其他文件。 |
| 订单信息 | 用户主动选购会员或主理人等服务时，记录所选商品、金额、订单号及支付状态，用于付款结果核对、权益开通、订单查询和售后处理。 |
| 发布内容 | 用户主动保存资料介绍、发送文字消息或发布活动时，处理其提交的文字，用于对应的会员展示、沟通及活动服务，并进行内容安全检测。 |
| 设备信息 | 获取设备系统、微信版本和屏幕尺寸，用于判断支付兼容性并适配图片裁剪界面。 |
| 摄像头 | 用户主动扫码添加主理人，或选择拍摄并提交认证材料时使用摄像头。 |
| 操作日志 | 记录会员资料访问时间及喜欢等互动操作，用于来访记录展示和互动状态同步。 |

当前“使用用户信息类型”弹窗应选择9项：手机号、选中的照片或视频信息、选中的文件、订单信息、发布内容、设备信息、摄像头、操作日志、自定义。其中设备信息对应支付兼容性判断与裁剪界面的实际系统信息调用，摄像头对应扫码和认证材料拍摄；操作日志包含会员详情页实际触发并保存的来访记录。选择后每一项都需填写真实用途。

身份证号码与车牌号需按实际认证处理确定：如果认证流程接收并使用材料中的完整身份证号或车牌号，应另行勾选相应标准类型，分别说明仅在用户主动申请实名认证或车辆认证时用于对应核验。不能因为号码位于图片/PDF中就忽略，也不能仅凭附件上传能力推定一定收集。只有业务实际要求并确认遮挡、不收集相应号码时，才不声明该项。

## 不应照搬或扩大声明的内容

- 微信登录未调用获取微信真实昵称、头像的接口；称呼由用户填写，照片由用户主动上传。不要写成自动读取微信昵称和头像。
- 城市、籍贯为用户手动选择；本轮源码未发现GPS定位或选择地理位置接口。
- 本轮源码仅发现复制邀请码、订单号或已同意交换的微信号到剪贴板，未发现读取剪贴板接口。后台若列有剪贴板，应核对其实际接口含义，不能把“复制”描述成“读取”。
- 新语音发送已暂停，不能将当前版本描述为正在采集聊天录音。历史录音模块及旧权限声明不等于功能已启用。
- 身份证、车辆等认证通过用户主动提交的证明附件进行。不要仅因启用认证就虚构结构化证件号、车牌或银行卡采集，也不要承诺上传材料绝不包含相关号码。
- 普通会员资料按展示设置使用；认证材料仅本人和授权审核人员读取。主理人私密建档及内部服务记录按相应业务权限访问，不能笼统承诺“所有资料仅本人可见”。

## 保存后核对

1. 查看生成后的指引，自定义条目应显示正式的信息名称与用途，不能残留“信息名称填”“用途填”、占位文本或空白用途。
2. 保留真实、可联系的开发者联系方式；不要填入示例邮箱或号码。
3. 确认本次保存已经生效，再重新提交代码审核。此次驳回针对后台声明，仅调整本填写稿并不等于后台已保存或已通过审核。
