## 使用目标

运营人员通过独立网页查看业务状态、核对主理人申请和会员认证材料、审核沙龙、查看套餐及订单。首期复用 `hlApi` 已有管理员接口，业务动作经云函数处理，不直接编辑数据库。

## 功能与边界

1. 登录：真实模式复用 `/admin/login` 的管理员码；服务端保存管理令牌，浏览器使用 HttpOnly 会话 Cookie。错误登录和过期会话必须可恢复，不在浏览器存储管理员码或 JWT。
2. 总览：展示现有后台统计，直接进入待办页面，不虚构收入、转化率或经营指标。
3. 主理人：按认证状态及关键词筛选、完整分页、查看资料、通过或拒绝认证并保存备注。
4. 会员认证：按用户编号查找申请，查看当前申请的核验信息与加密材料，经管理员受控接口审核；绑定当前申请 ID，拒绝陈旧审核。教育与资产通过需来源、凭据及核验结论。
5. 沙龙：查看、筛选、审核通过、拒绝或取消；状态变更显示确认界面，报名和人数不允许通过后台手改。
6. 套餐：展示服务端配置。六档虚拟商品的价格、时长与次数由现有固定商品规则决定，首期只读；后续商品修改需与微信商品和代码目录一致。
7. 订单：按状态、履约状态、商品、用户编号、订单/套餐/交易号搜索；完整分页；详情只读，待复核状态明确。首期无退款、补发权益或直接改状态按钮。
8. 网关：只监听本机，限定 Host、Origin 和请求大小；仅代理所需 `/admin` 白名单，禁止任意 MCP 操作、支付内部回调和业务下单接口；所有管理与材料响应不缓存。

## 接入方式

`admin-console/` 独立 React + Vite 项目；本机 Node 网关提供静态页面和受控管理代理，真实模式通过官方 CloudBase MCP 的已有登录调用明确环境 `cloud1-d2gza7q9c8d69c721` 的 `hlApi`。本轮先本地搭建，不配置公网域名、不部署云函数或修改云端支付开关。将来公网运营版本需要独立部署及账号权限设计，不能直接把本机网关暴露公网。
